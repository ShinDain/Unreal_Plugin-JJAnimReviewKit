Annotations add `endFrame` (INDEX_NONE means Frame), `groupName`, `bones` snapshot, `images` (asset-directory-relative notes/id/file). Group JSON has independent schemaVersion 1, skeleton path and groups{name,side,bones}; color is derived. Notes functions remain asset/UI/render independent. Saved/JJAnimReview is the bundle boundary; BoneGroups under plugin BaseDir is the only additional persistence boundary and is written only on explicit group save.

- Reflected property names use `FJsonObjectConverter` lowerCamelCase, including boolean `b` prefixes. Unknown/missing required fields or unsupported schema versions fail closed.
- `review.json`: schemaVersion, asset, take, takeNumber, contentId, createdUtc, updatedUtc, profile, profileSettings, bEstimatedProfile, checkStatus, warnings, checks, annotations, poseDifferences, images.
- `pose.json`: schemaVersion, contentId, samplingPolicy, durationSeconds, rateNumerator/Denominator, boneNames, parentIndices, notifyTimesSeconds, samples. Each sample has timeSeconds, sourceFrame, componentTransforms and cumulative rootMotion.
- Transforms contain translationCm, rotationDegrees and scale, each an x/y/z object. Rotation x=roll, y=pitch, z=yaw. Component space includes root movement; never add root motion a second time. Parent indices permit local-space reconstruction.
- `pose_md5_v2`: full source-frame grid plus endpoint, hierarchy/names, timing, component transforms, Raw-derived root motion and notify start times. Translation rounds to 0.001 cm; normalized quaternion and scale to 0.000001; times to 0.000001 s. Quaternion components are symmetrically rounded to integer magnitudes before choosing the sign by the first nonzero component in W/X/Y/Z order; those four canonical integers are hashed in that order. This merges yaw +180/-180 and q/-q, including near-zero W and half-step ties. UTF-8 length-prefixed integer strings avoid JSON order/locale/negative-zero ambiguity. MD5 is a non-security identity, not a tamper guarantee.
- JSON schema is v2 for review and pose, independently of pose_md5_v2. Older schema versions are rejected before shape conversion. Legacy folders and zero-padded take names are ignored and never migrated or pruned.
- The identity detects sampled pose/notify differences within that precision; it does not claim to cover every curve or unsampled change. Profile/check/capture settings do not affect it. A future hash policy change must be versioned and migrated explicitly.
- Default thresholds: foot_sliding 2 cm, penetration 1 cm, pop 45 deg, joint_limits 5 deg tolerance, root_discontinuity 10 cm, loop_mismatch 2 cm/deg, socket_drift 2 cm. Contact height 3 cm, vertical speed 10 cm/s. Estimated foot contacts use each bone's full-clip minimum Z and a separate horizontal swing ceiling of 50 cm/s; explicit profiles retain authored ground/contact rules. Free/Locked constraint axes are excluded, and estimated joint-limit exceedances are warnings only. Estimated names split on `_`, `-`, `.`; exact foot/ball and hand/palm tokens; exclude ik/twist/ctrl tokens. Unmatched rigs require a user profile.
- Asset directory is case-preserving ASCII-alphanumeric asset name (other characters become _) plus six lowercase hex digits from MD5 of the lowercase object path UTF-8 bytes. Names are take_1, take_2, etc.; only ASCII positive integers without leading zeros and within int32 are owned. Numeric ordering is independent of timestamps. Collision checks compare existing review.asset before recovery/staging; Save also verifies requested identity.
- Same-content refresh preserves annotations/images/differences. New-content take carries open annotations with stable IDs and original take/content ID. The latest take owns current resolution state. `SetAnnotationState` updates only the supplied array; R3 can supply/save just the latest take. Historical snapshots need not be rewritten to permit pruning.
- Retain 10 takes by default. Always keep latest and the AuthoredTake of each annotation still open in the latest take. Delete other takes oldest first, including intermediates containing only carried copies. Historical open/resolved copies do not control retention. Distinct protected authored takes can still exceed the configured limit.
- Write sequence: exclusive per-asset handle → recover any marker → stage `.next` files and `.previous` backups → `.transaction` marker → replace pose/md/review (last) → remove marker to commit → cleanup. Interrupted existing takes roll back all three files; interrupted new takes discard core files. This is process-crash recovery, not a filesystem power-loss atomicity guarantee. External readers must ignore a take while `.transaction` exists.
- Read-only UI opens create no directories/locks and perform no recovery; an observed transaction marker produces a retry error. Writer opens retain exclusive recovery/save/retention behavior. Read-only access is not an atomic filesystem snapshot across concurrent writes.
- Markdown has a 6000 UTF-8 byte cap including footer, no tokenizer dependency; 240 bytes are reserved for the footer. Overflow stays in JSON with separate omitted-item counts for failures/warnings/current/previous/other; failures precede warnings, passed/skipped counts and bounded skipped names share one line. Check details cap at five lines per check; after budget exhaustion, line factories are not evaluated. Annotation headings are emitted together with the first included item, so empty or fully omitted sections leave no orphan heading. This is a byte budget, not a measured 2000-token claim.
- Comparison ranges cap at three per bone and fifty overall, with omitted-range counts. Comparison is informational and never changes CheckStatus or exit code. Capture assumes mesh +Y front, supports ForwardYawOffset (default 90, profile override), and always elevates the last angle, including a single-angle sheet. Pose instruction text describes a parent-space delta (component space for the root).
- Corrupt take errors include the exact folder and instructions to move that folder outside the asset directory, preserving it for diagnosis, then run again. No automatic removal or silent overwrite occurs. Moving history can remove annotation provenance from the active store; recover it manually if needed.
