# JJAnimReviewKit 사용자 안내서

대상: AnimSequence를 검토하고 수정 지시를 전달하는 애니메이터·개발자. UE 5.8 / Win64, 2026-11-07의 소스 기준.

애니메이션을 수치로 검사하고, 여러 프레임을 모은 컨택트 시트와 프레임별 주석으로 수정 사항을 전달하는 도구다. 플러그인이 원본 애니메이션을 수정·저장하지는 않는다. 검토 결과는 `Saved/JJAnimReview/`에 저장한다.

이 안내서는 R6의 탭 배치·그룹 관리·메시 칠하기와 기존 검사·캡처·주석·비교 경로를 설명한다. Codex는 자동화 테스트나 GUI 검증을 수행하지 않았다(끝의 "검증 범위" 참고).

관련 문서: [기술 구조](ARCHITECTURE.ko.md), [AI에게 전달할 규칙](../AI_USAGE.md), [엔진 호환 가정](../PORTING.md).

## 1. 처음 준비하기

**정상 순서: 리뷰 묶음 만들기 → 리뷰 주석 탭 열기 → 새로고침 → 주석 작성.** 애니메이션을 고친 뒤에는 다시 묶음을 만들고 새로고침한다. 재생성 전의 오래된 리뷰에 주석을 저장하면 거부된다.

1. `Plugins/JJAnimReviewKit/`에 설치하고 에디터 타깃을 빌드한다. 기본 활성화 descriptor를 사용한다.
2. 콘텐츠 브라우저에서 검토할 **AnimSequence**를 연다. Control Rig·Level Sequence 결과라면 먼저 AnimSequence로 준비한다.
3. 애니메이션 또는 Skeleton에 Preview Mesh가 있는지 확인한다. 수치 검사와 달리 이미지 생성에는 미리보기 메시와 렌더링 가능한 GUI 에디터가 필요하다.
4. 애니메이션 에디터 툴바의 **리뷰 묶음 만들기**, **리뷰 주석**을 찾는다.

현재 Ter의 로컬 사용에서는 Plugins 창 토글로 `.uproject`에 플러그인 항목을 저장하지 않는다. 개인 설치 폴더와 출력물을 팀 repo에 함께 올리는 것으로 오해하지 않도록 설치 정책을 구분한다.

> **캡처 자리 AN-01 — 시작 화면**  
> AnimSequence 에디터에서 에셋 이름, Preview Mesh, 두 리뷰 버튼을 표시한다. Level Sequence 창과 혼동하지 않게 제목도 포함한다.  
> 삽입 파일: `images/anim-01-toolbar.png`

## 2. 첫 리뷰 묶음 만들기

1. 대상 AnimSequence를 연 상태에서 **리뷰 묶음 만들기**를 누른다.
2. 처리 후 대화상자에 표시된 take 폴더 경로를 복사해 탐색기로 연다. 오류라면 경로 대신 오류 문구가 표시된다.
3. `review.md`에서 추정 프로필 경고, 검사 실패·경고, 주석을 읽는다.
4. `sheet.png`가 있으면 열어 자세·타이밍을 확인한다. 이미지가 없다면 `review.json`의 경고 또는 실행 로그를 확인한다. 수치 리뷰가 저장돼도 시트 생성은 건너뛸 수 있다.

| 파일 | 언제 열면 되나 |
|---|---|
| `review.md` | 가장 먼저 읽는 짧은 요약. 최대 6000 UTF-8 바이트이므로 생략 수 확인 |
| `review.json` | 검사·주석·비교의 전체 구조화 결과가 필요할 때 |
| `pose.json` | 전체 포즈 샘플과 분석이 필요할 때. 일반 리뷰에서는 열 필요 없음 |
| `sheet.png` | 여러 각도·프레임에서 동작의 인상을 판단할 때. GUI 캡처 성공 시에만 존재 |

기본 위치는 `Saved/JJAnimReview/<에셋 이름>_<해시6>/take_<번호>/`다. 이름의 영숫자 외 문자는 `_`로 바꾸고 대소문자는 유지한다. 번호는 `take_1`, `take_2`, …, `take_12`처럼 0 채움 없이 증가한다. 이전 긴 폴더·`take_000001`은 읽거나 정리하지 않는다. 새 형식의 review.json·pose.json은 schema v2다.

테이크는 포즈나 Notify 시작 시각이 바뀌면 증가한다. 커브 값·Notify 이름만 바꾸면 증가하지 않는다(평가 포즈가 바뀌면 증가). 에셋 이동·이름 변경은 새 폴더를 만든다. 해시 충돌·다른 에셋 경로가 발견되면 덮어쓰지 않고 오류를 낸다.

기본 시트 설정은 최대 6프레임과 4각도다. 짧은 클립은 중복 없는 프레임만 나온다. 첫·끝 프레임과 Notify 시점을 우선하고 남는 구간을 채운다. 기본 셀 크기는 256이며 전체 레이아웃 제한에 따라 작아질 수 있다.

정면은 UE 마네킹의 메시 +Y다(`ForwardYawOffset=90`). 각도는 정면 기준 상대 yaw이며 마지막 각도는 위에서 내려다본다. 명시 프로필의 `Settings.ForwardYawOffset`으로 정면을 바꿀 수 있다. 모든 열은 같은 카메라 거리·높이를 사용한다. 파랑=왼쪽, 빨강=오른쪽, 초록=가운데, 노랑=그 프레임의 주석 대상이다. 선은 캡처 후 겹치므로 메시에 가려지지 않는다.

> **캡처 자리 AN-02 — 리뷰 결과**  
> take 폴더의 파일 목록과 실제 `sheet.png` 예시를 배치한다. 시트의 각도·프레임 표기를 확대하고, 함께 생성된 `review.md`의 실패 또는 경고 한 항목을 보여 준다.  
> 삽입 파일: `images/anim-02-bundle.png`

## 3. 프레임과 본에 수정 의견 남기기

**먼저 리뷰 묶음을 만들고 탭을 새로고침한다.** 방향 축 ±X/±Y/±Z는 **월드 축**이다. 그룹 쪽이나 본 로컬 축을 뜻하지 않는다.

- 단일 주석은 **단일 프레임**을 누르고 현재 프레임에서 추가한다. 구간은 **시작=현재 프레임**, 타임라인 이동, **끝=현재 프레임** 순서로 정한다. `0 ≤ 시작 ≤ 끝 ≤ 마지막 샘플 프레임`이어야 하며 목록 클릭은 시작으로 이동한다. 표시는 `[시작−2, 끝+2]`에서 보인다.
- 대상 선택기의 첫 항목은 Persona에서 선택한 본이다. Ctrl+클릭으로 여러 본을 선택하면 이름 없는 여러 본 주석이 된다. 그룹을 고르면 그룹 이름과 현재 본 목록 사본을 주석에 저장하므로 나중에 그룹을 고쳐도 과거 지적은 유지된다.
- **선택 본으로 그룹 저장**: 본 다중 선택 → 필요하면 **자식 본 포함** → 이름 입력 → 쪽 확인(왼쪽/오른쪽/가운데; 파일 값은 left/right/center) → 저장. `_l`/`_r` 다수로 쪽을 추정하며 직접 고칠 수 있다. 그룹 선택 뒤 **이름 변경**, **그룹 삭제**도 가능하다. 이름이 겹치면 기존 그룹을 유지하고 `이름 2`, `이름 3`처럼 비어 있는 첫 번호를 붙인다. 이름 변경도 같은 규칙이다. 삭제하거나 이름을 바꾼 기본 그룹은 빈 사용자 override로 숨긴다. **기본 그룹 복원**은 이 숨김 항목만 지운다. 같은 이름으로 본 목록을 바꾼 기존 사용자 override와 이름을 바꾼 사본은 보존한다.
- 기본 그룹은 머리·몸통·왼팔·왼손가락·오른팔·오른손가락·왼다리·오른다리다. twist를 포함하고 `ik_*`·attach·`weapon_*`는 제외한다. 기준 본 16개 중 12개 미만이면 기본 템플릿을 적용하지 않고 탭에 안내한다.
- 그룹 파일은 명시 저장 때만 `Plugins/JJAnimReviewKit/BoneGroups/<스켈레톤 이름>_<해시6>.json`에 생긴다. 사용자 그룹은 같은 이름의 기본 그룹을 대체한다. **플러그인을 공유할 때 BoneGroups 폴더도 함께 커밋·공유한다.** 쓰기 실패는 탭 오류로 나온다.
- **그룹 표시**는 모든 그룹을 흐리게 칠한다. **선택 그룹 메시 칠하기**는 고른 그룹을 칠하며 그룹을 바꿔도 켜진 상태를 유지한다. 첫 항목이면 Persona 선택 본(자식 포함 설정 반영)을 칠한다. 주석 표시는 두 층보다 우선하고, 선택한 주석은 원색·다른 열린 주석은 흐린 색이다. 같은 본의 주석이 겹치면 선택한 주석, 그룹 목록의 앞선 그룹, 같은 그룹에서는 먼저 저장된 주석 순서로 정한다. 칠하지 않은 정점은 중립 회색이고 여러 본의 가중치 비율로 색을 섞는다. 기본 8그룹은 고정 색, 사용자 그룹은 이름에서 정해지는 안정 색이며 목록에도 색 표시가 붙는다. 이름 없는 본 대상은 별도 고정 색이다. 시트·JSON에는 칠하기를 넣지 않는다.
- 저장한 주석을 선택하고 **선택 주석에 PNG/JPG 첨부**로 파일을 복사한다. 목록 아래 경로 버튼으로 기본 프로그램에서 열고 **첨부 해제**로 연결을 끊는다. 파일은 에셋 폴더의 `notes/<AnnotationId>/`에 있으며 take 밖에서 공유된다. 이월 시 같은 경로를 유지하고, 보존 정리 뒤 남은 어느 take에서도 참조하지 않는 폴더만 삭제한다.

1. **리뷰 주석**을 연다. 이 탭은 **기본 출력 폴더의 최신 리뷰**를 사용한다.
2. 애니메이션 타임라인에서 문제 프레임으로 이동하고 필요한 본을 선택한다.
3. 주석 텍스트를 입력한다. 예: “착지 뒤 왼발이 앞으로 밀림. 지면에 고정되는 느낌 필요”.
4. 방향을 ±X/±Y/±Z 중 선택하고 정도를 `little` 또는 `much`로 지정한다. 방향은 선택적 전달 정보이므로 문장에 의도와 기준도 적는다.
5. **현재 위치에 추가**를 누른다. 현재 프레임과 선택 본을 가진 주석이 저장된다. 본이 선택되지 않았다면 본 지정 없는 주석이 된다.
6. 목록의 주석을 누르면 해당 프레임으로 이동한다. 텍스트·방향·정도를 고친 뒤 **선택 주석 수정**으로 저장한다.
7. 수정 결과를 확인한 뒤 **해결**을 누른다. 다시 필요하면 **다시 열기**, 불필요한 항목은 **삭제**를 사용한다.

**주석 표시 ±2f**를 켜면 [시작−2, 끝+2]에서 열린 주석 대상을 칠한다(선택한 주석은 해결 상태여도 표시). 선택 행은 배경으로 구분한다. 기준점과 방향 화살표는 유지한다. 이전 버전에서 넘어온 주석은 노란색으로 구분한다. 원본 애니메이션을 수정한 뒤 탭이 오래된 내용을 가리킨다면 리뷰를 다시 만들고 **새로고침**한다.

> **캡처 자리 AN-03 — 주석 추가와 이동**  
> 선택 본, 현재 프레임, 주석 입력란, 방향·정도, 현재 위치에 추가 버튼을 함께 촬영한다. 두 번째 화면에는 저장된 주석의 해결/다시 열기 위치를 표시한다.  
> 삽입 파일: `images/anim-03-annotations.png`

탭 배치는 위에서 아래로 다음 순서다.

1. 새로고침·주석 표시 ±2f, 이전 테이크 고스트·take 선택·고스트 옆 간격(cm).
2. 구분선 뒤 그룹 상태(문제가 있을 때만), 그룹 표시, 그룹 선택·삭제·기본 그룹 복원, 이름·쪽·저장·이름 변경, 자식 본 포함·선택 그룹 메시 칠하기.
3. 남은 높이를 채우는 주석 목록.
4. 구분선 뒤 텍스트, 방향·정도, 프레임 구간, 추가·수정·포즈 지시, 이미지 첨부·목록, 상태 문구.

칠하기는 끄기·표시 대상 없음·탭 닫기·애니메이션/메시 변경 때 원래 머티리얼과 정점 색으로 돌아간다. Persona의 본 가중치·모프 타깃 보기가 켜지면 칠하지 않는다. 엔진 머티리얼·셰이더 또는 CPU 정점 영향 데이터가 없으면 본 가중치 한 색 보기와 그룹 색 선으로 대체하고 상태에 이유를 쓴다. 정점 수가 맞지 않는 LOD는 생략한다. 선이 남는 곳과 선 고스트의 관절 점은 작은 주황색(5px)이며 메시 앞에 강제로 그리지 않는다. 손가락·twist 이름의 세부 본은 점을 생략하고 선은 유지한다. 시트와 선 고스트는 LOD0 스킨 가중치 본만 가장 가까운 가중치 조상과 잇고, 메시 정보가 없으면 모든 본을 잇는다.

## 4. 원하는 포즈를 보여 주며 지시하기

1. 문제 프레임에서 재생을 멈춘다.
2. Persona 미리보기의 본 조작으로 원하는 포즈를 만든다. 원본에 키를 굽는 작업과 구분한다.
3. 의도를 텍스트로 입력하고 **포즈 지시 저장**을 누른다. 시작·끝 구간과 무관하게 **현재 프레임 하나(Frame = EndFrame)**에 기록한다. 구간이 잡혀 있었다면 상태에 이를 알린다.
4. 미리보기에서 직접 움직여 수정 기록이 있는 본만 원본 대비 로컬(부모 본 기준) 이동·회전 차이가 주석에 저장된다. 후처리·압축에 따른 VB 등 다른 본의 차이는 제외한다. 루트도 직접 움직였을 때만 기록한다. 목록의 주석 텍스트 뒤에 `[Preview pose instruction; parent-space]`가 붙는다. 차이가 0.1cm / 0.5deg 기준을 넘지 않으면 저장할 포즈 변경이 없다는 메시지가 나온다.
5. 저장 후 미리보기 수정은 남아 있다. 포즈 지시 저장 바로 아래의 **본 수정 초기화** 버튼으로 지운 뒤 원본 동작을 확인한다. 초기화도 **Ctrl+Z**로 되돌릴 수 있다. 수정이 없으면 안내만 표시한다.

고친 본의 로컬 차이만 기록한다. 나열되지 않은 본의 로컬 변환을 유지하면 자식은 FK로 따라 움직인다. 손의 무기 잡기 같은 월드 위치 유지 관계는 자동으로 보존되지 않으므로 텍스트와 다른 본 지시도 함께 확인한다. 앞뒤 프레임의 연결은 작업 AI가 판단한다.

이 버튼은 애니메이션 수정 지시를 기록한다. 생성된 주석을 전달받은 작업자가 별도 작성 도구로 원본을 수정해야 한다.

> **캡처 자리 AN-04 — 포즈 지시**

## 5. 수정 후 이전 버전과 비교하기

1. 실제 AnimSequence를 수정한 뒤 다시 리뷰 묶음을 만든다.
2. 포즈 내용이 바뀌면 새 take가 생기고, 이전 take의 열린 주석이 이월된다. 내용이 같으면 최신 take를 갱신한다.
3. `review.md`의 테이크 비교에서 차이가 큰 본과 프레임 구간을 확인한다.
4. 주석 탭을 새로고침하고 **이전 테이크 고스트**를 켠다. 목록에서 비교할 이전 take를 고른다. **고스트 옆 간격(cm)**은 기본 0, -500~500, 스핀 조절 10cm 단위다. 양수는 캐릭터 정면 기준 오른쪽, 음수는 왼쪽으로 메시·선 고스트를 옮긴다. 정면은 시트와 같은 프로필 ForwardYawOffset(기본 마네킹 +Y)을 쓰므로 마네킹의 오른쪽은 컴포넌트 -X다. 값은 탭이 열린 동안만 유지하고 저장하지 않는다. 간격 변경은 다음 그리기에 반영되며 리뷰 묶음·포즈 지시·시트에는 영향이 없다.
5. 현재 메시 위 자홍색 반투명 메시 고스트와 비교하며 타임라인을 움직인다. **고스트를 처음 켤 때 셰이더 준비 시간이 있으며 GUI 4회차에서는 약 5초가 관측됐으며 환경에 따라 길어질 수 있다.** 에디터 세션마다 코드로 만든 임시 머티리얼의 SkeletalMesh·MorphTargets·Clothing·MeshDeformer 지원 셰이더를 한 번 비동기로 컴파일하며, 이때는 고스트를 숨기고 "고스트 머티리얼 준비 중"을 표시한다. 숨은 Substrate 변환을 사용할 수 없어 기존 변환 경로로 처리하는 환경에서는 세션 첫 켜기에 큰 레벨이 열려 있으면 잠깐 멈출 수 있다. 실패하면 가중치 본만 잇는 선 고스트로 대체하며 상태에 이유를 쓴다. 플러그인 머티리얼 에셋과 원본 메시 변경은 없다. 고스트 위치는 현재 미리보기 애니메이션의 루트 모션·고정 설정을 따른다. **LoopAndReset**과 **Loop**에서 컴포넌트에 루트 모션을 적용하면 고스트 take 자신의 루트 모션을 보존하고, 기준 변환에서 현재 주기의 적용분을 빼 이중 이동을 방지한다. **Ignore + 루트 모션 에셋**, 또는 **루트 모션 적용 없이 bForceRootLock이 켜진 에셋**에서는 모든 고스트 본을 해당 시각의 고스트 루트 기준 상대 변환 × 고정 루트로 옮긴다. 고정 루트는 RootMotionRootLock이 **AnimFirstFrame**이면 고스트 take의 pose.json 0초 루트, **RefPose**이면 현재 미리보기 메시의 루트 참조 포즈, **Zero**이면 항등이다. AnimFirstFrame에서 두 take의 첫 루트 차이는 위치에 남는다. 루트 모션도 강제 고정도 없으면 기존 컴포넌트 기준으로 그린다. 물리 시뮬레이션 중에는 보수적으로 루트 보정을 생략한다. **Loop**의 이전 주기 누적·바닥 경계 래핑은 기준에 남으며, 루프 경계·역재생·회전 누적·물리 혼합·턴테이블·미러에서는 정확히 겹치지 않을 수 있다. 끄기·take 변경·탭 닫기·애니메이션/메시 변경 때 고스트 컴포넌트를 해제한다.
6. 이월된 의견이 실제로 해결됐는지 확인하고 해당 주석을 해결 처리한다.

보존 기본값은 10개다. 최신 take와 최신 리뷰의 열린 주석이 처음 작성된 take는 보호되므로 10개를 넘게 남을 수 있다. 이전 `pose_md5_v1` take는 비교·고스트 대상에서 제외된다. 포즈 내용이 다른 v2 take가 둘 이상 있어야 v2끼리 비교할 수 있다. 같은 내용을 반복 실행해도 새 비교 버전은 생기지 않는다.

> **캡처 자리 AN-05 — 버전 비교**  
> 이전 take 선택 목록, 고스트 체크박스, 현재 포즈와 자홍색 메시 고스트를 함께 촬영한다. 이월 주석 표시도 한 항목 포함한다.
> 삽입 파일: `images/anim-05-ghost.png`

## 6. 프로젝트에 맞는 검사 기준 설정하기

콘텐츠 브라우저의 Data Asset 생성에서 `JJAnimReviewProfile`을 선택해 사용자가 프로필을 만든다. Skeleton, 발 본, 관통 검사 본, 바닥 높이, 소켓·본 쌍과 검사별 임계값을 지정한다. 프로필이 없으면 이름으로 추정하며 경고가 붙는다.

> **캡처 자리 AN-06 — 프로필 에셋**  
> Data Asset 생성 대화상자에서 `JJAnimReviewProfile`을 고르는 화면과, 만든 프로필의 Details(Skeleton·발 본·바닥 높이·검사별 임계값)를 촬영한다.  
> 삽입 파일: `images/anim-06-profile.png`

| 검사 ID | 확인 내용 | 기본 임계값 |
|---|---|---|
| `foot_sliding` | 접지로 판정된 구간에서 발의 수평 이동 | 2cm |
| `penetration` | 지정 본이 바닥보다 내려간 깊이 | 1cm |
| `pop` | 본의 급격한 움직임 변화 | 회전 45deg; 이동 급변은 root 기준도 사용 |
| `joint_limits` | PhysicsAsset 관절 한계의 근사 초과 | 여유 5deg |
| `root_discontinuity` | 루트 이동의 급변 | 10cm |
| `loop_mismatch` | 루프의 시작·끝 포즈 차이 | 2cm |
| `socket_drift` | 지정한 소켓·본 쌍 거리의 변화 | 2cm |

접지 기본값은 높이 허용 3cm, 수직 속도 10cm/s다. 추정 프로필은 발 본별 클립 최저 높이를 바닥으로 쓰고, 수평 속도 50cm/s를 넘는 구간(발을 휘두르는 중)은 접지에서 뺀다.

`joint_limits`는 PhysicsAsset 제약 중 Limited 축만 검사한다(Free·Locked 축 제외). 같은 본·같은 축이 연속 프레임에서 초과하면 한 구간으로 합치고 가장 큰 초과량을 남긴다. 추정 프로필에서는 초과가 경고, 명시 프로필에서만 실패다. 검사는 앞 10000샘플로 제한되며 해당 시 경고한다. 루프 끝점과 내용 식별은 전체 포즈를 사용한다. 검사 통과만으로 연기 품질이 승인되는 것은 아니다.

현재 툴바 실행에는 프로필 선택기가 없으므로, 프로필을 지정한 검사는 에디터 콘솔로 실행한다. 주석 탭과 연결하려면 Output 인자는 생략해 기본 경로를 쓴다.

```text
JJAnimReview.Create /Game/Anims/Walk.Walk /Game/Review/WalkProfile.WalkProfile
JJAnimReview.Sheet /Game/Anims/Walk.Walk /Game/Review/WalkProfile.WalkProfile
```

프로필 없이 별도 출력 폴더를 지정하려면 중간 자리에 `-`를 쓴다. 예: `JJAnimReview.Create /Game/Anims/Walk.Walk - SessionA`. 다만 그 폴더는 현재 주석 UI가 읽는 기본 경로와 다르다. 툴바를 다시 누르면 프로필 없는 기본 요청으로 리뷰가 갱신된다.

## 7. AI에게 전달하고 반복하기

기본 출력의 take 폴더 경로와 수정 목표를 전달한다. 예: “이 리뷰의 미해결 주석을 반영해 줘. 먼저 review.md를 읽고, 필요하면 review.json을 확인해 줘.” AI 전달 원칙은 [AI_USAGE.md](../AI_USAGE.md)를 따른다.

화면 없는 수치 검사는 다음 명령을 사용한다. 경로는 환경에 맞게 바꾼다.

```powershell
& '<Engine>/Engine/Binaries/Win64/UnrealEditor-Cmd.exe' '<Project>/Example.uproject' -run=JJAnimReview -Asset=/Game/Anims/Walk.Walk -nullrhi -unattended -nosplash
```

선택 인자는 `-Profile=<에셋 경로>`, `-Output=<하위 폴더>`다. 종료 코드 **0**은 실행 완료·검사 실패 없음(경고는 가능), **1**은 검사 실패 있음, **2**는 실행 오류다. `-Sheet`를 주더라도 commandlet/nullrhi에서는 이미지를 만들지 않는다. 이미지가 필요하면 GUI에서 생성한다.

## 8. 막혔을 때

| 증상 | 조치 |
|---|---|
| 툴바 버튼이 없음 | AnimSequence 에디터인지, 플러그인 모듈 빌드·로드 여부 확인 |
| sheet.png가 없음 | GUI·렌더링·Preview Mesh, 리뷰 경고 확인 |
| 발 검사가 이상함 | 추정 프로필의 본·바닥 기준을 검토하고 명시 프로필 사용 |
| 주석을 추가할 수 없음 | 기본 출력에 리뷰 생성 → 탭 새로고침. 원본이 바뀌었으면 재생성 |
| 별도 Output 리뷰가 안 보임 | 주석·고스트 UI는 기본 출력 폴더만 읽음 |
| 이전 take가 고스트 목록에 없음 | 이전 v2 take 유무와 보존 여부 확인 |
| 손상·transaction 오류 | 주석 탭(읽기 전용)에서는 복구하지 않는다. 같은 에셋에 리뷰 묶음 만들기를 다시 실행하면 복구를 시도한다. 반복되면 오류가 지목한 폴더를 보존해 출력 에셋 폴더 밖으로 이동 후 재생성 |
| joint_limits 경고가 많음 | 추정 프로필이면 오탐일 수 있음. 메시지의 axis·angle·limit을 확인하고 필요하면 명시 프로필로 임계값 조정 |

## 검증 범위

R1~R4-fix2 시점의 Claude headless 테스트 21개 통과 기록은 R5의 검증 결과가 아니다. R5-fix는 Claude 재리뷰에서 빌드·30/30 테스트 승인 기록이 있다. R6는 기존 테스트 파일을 수정하거나 실행하지 않는다. 실제 빌드·커맨드렛 결과는 shared handoff의 최신 Codex 항목을 따른다. GUI의 크래시 해소·열별 포즈·조명·그룹·첨부·상태 복원은 사용자 확인 대상이다. 캡처 자리는 실제 화면을 넣을 위치 표시다.

R6 시트는 그림자 없음·고정 카메라·회색 배경을 유지하며 광원 1.6 / 하늘 0.8 / ColorOffset 0.08로 낮췄다. 하얗게 바랜 느낌 개선과 등 쪽 팔다리 가독성은 사용자 GUI 확인이 필요하다.
