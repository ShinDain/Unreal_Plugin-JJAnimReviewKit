# JJAnimReviewKit 사용자 안내서

대상: AnimSequence를 검토하고 수정 지시를 전달하는 애니메이터·개발자. UE 5.8 / Win64, 2026-11-07의 소스 기준.

애니메이션을 수치로 검사하고, 여러 프레임을 모은 컨택트 시트와 프레임별 주석으로 수정 사항을 전달하는 도구다. 플러그인이 원본 애니메이션을 수정·저장하지는 않는다. 검토 결과는 `Saved/JJAnimReview/`에 저장한다.

이 안내서는 현재 코드에 있는 검사·캡처·주석·비교 경로를 설명한다. 검사·저장·테이크·주석 편집·비교 로직은 자동화 테스트로 확인했지만, 툴바·주석 탭·시트·고스트 등 GUI 화면은 아직 실행 검증하지 않았다(끝의 "검증 범위" 참고).

관련 문서: [기술 구조](ARCHITECTURE.ko.md), [AI에게 전달할 규칙](../AI_USAGE.md), [엔진 호환 가정](../PORTING.md).

## 1. 처음 준비하기

1. `Plugins/JJAnimReviewKit/`에 설치하고 에디터 타깃을 빌드한다. 기본 활성화 descriptor를 사용한다.
2. 콘텐츠 브라우저에서 검토할 **AnimSequence**를 연다. Control Rig·Level Sequence 결과라면 먼저 AnimSequence로 준비한다.
3. 애니메이션 또는 Skeleton에 Preview Mesh가 있는지 확인한다. 수치 검사와 달리 이미지 생성에는 미리보기 메시와 렌더링 가능한 GUI 에디터가 필요하다.
4. 애니메이션 에디터 툴바의 **리뷰 묶음 만들기**, **리뷰 주석**을 찾는다.

현재 Ter의 로컬 사용에서는 Plugins 창 토글로 `.uproject`에 플러그인 항목을 저장하지 않는다. 개인 설치 폴더와 출력물을 팀 repo에 함께 올리는 것으로 오해하지 않도록 설치 정책을 구분한다.

> **캡처 자리 AN-01 — 시작 화면**  
> AnimSequence 에디터에서 에셋 이름, Preview Mesh, 두 리뷰 버튼을 표시한다. Level Sequence 창과 혼동하지 않게 제목도 포함한다.  
> 삽입 파일: `images/anim-01-toolbar.png`

## 2. 첫 리뷰 묶음 만들기

1. 대상 AnimSequence를 연 상태에서 **리뷰 묶음 만들기**를 누른다.
2. 처리 후 대화상자에 표시된 take 폴더 경로를 복사해 탐색기로 연다. 오류라면 경로 대신 오류 문구가 표시된다.
3. `review.md`에서 추정 프로필 경고, 검사 실패·경고, 주석을 읽는다.
4. `sheet.png`가 있으면 열어 자세·타이밍을 확인한다. 이미지가 없다면 `review.json`의 경고 또는 실행 로그를 확인한다. 수치 리뷰가 저장돼도 시트 생성은 건너뛸 수 있다.

| 파일 | 언제 열면 되나 |
|---|---|
| `review.md` | 가장 먼저 읽는 짧은 요약. 최대 6000 UTF-8 바이트이므로 생략 수 확인 |
| `review.json` | 검사·주석·비교의 전체 구조화 결과가 필요할 때 |
| `pose.json` | 전체 포즈 샘플과 분석이 필요할 때. 일반 리뷰에서는 열 필요 없음 |
| `sheet.png` | 여러 각도·프레임에서 동작의 인상을 판단할 때. GUI 캡처 성공 시에만 존재 |

기본 위치는 `Saved/JJAnimReview/<에셋 키>/take_<번호>/`다. 에셋 키와 번호는 도구가 만든다. 파일을 임의로 덮어쓰기보다 다음 리뷰 실행으로 갱신한다.

기본 시트 설정은 최대 6프레임과 4각도다. 짧은 클립은 중복 없는 프레임만 나온다. 첫·끝 프레임과 Notify 시점을 우선하고 남는 구간을 채운다. 기본 셀 크기는 256이며 전체 레이아웃 제한에 따라 작아질 수 있다.

> **캡처 자리 AN-02 — 리뷰 결과**  
> take 폴더의 파일 목록과 실제 `sheet.png` 예시를 배치한다. 시트의 각도·프레임 표기를 확대하고, 함께 생성된 `review.md`의 실패 또는 경고 한 항목을 보여 준다.  
> 삽입 파일: `images/anim-02-bundle.png`

## 3. 프레임과 본에 수정 의견 남기기

1. **리뷰 주석**을 연다. 이 탭은 **기본 출력 폴더의 최신 리뷰**를 사용한다.
2. 애니메이션 타임라인에서 문제 프레임으로 이동하고 필요한 본을 선택한다.
3. 주석 텍스트를 입력한다. 예: “착지 뒤 왼발이 앞으로 밀림. 지면에 고정되는 느낌 필요”.
4. 방향을 ±X/±Y/±Z 중 선택하고 정도를 `little` 또는 `much`로 지정한다. 방향은 선택적 전달 정보이므로 문장에 의도와 기준도 적는다.
5. **현재 위치에 추가**를 누른다. 현재 프레임과 선택 본을 가진 주석이 저장된다. 본이 선택되지 않았다면 본 지정 없는 주석이 된다.
6. 목록의 주석을 누르면 해당 프레임으로 이동한다. 텍스트·방향·정도를 고친 뒤 **선택 주석 수정**으로 저장한다.
7. 수정 결과를 확인한 뒤 **해결**을 누른다. 다시 필요하면 **다시 열기**, 불필요한 항목은 **삭제**를 사용한다.

**주석 표시 ±2f**를 켜면 주석 시점 주변에서 본 위치에 표시한다. 이전 버전에서 넘어온 주석은 노란색으로 구분한다. 원본 애니메이션을 수정한 뒤 탭이 오래된 내용을 가리킨다면 리뷰를 다시 만들고 **새로고침**한다.

> **캡처 자리 AN-03 — 주석 추가와 이동**  
> 선택 본, 현재 프레임, 주석 입력란, 방향·정도, 현재 위치에 추가 버튼을 함께 촬영한다. 두 번째 화면에는 저장된 주석의 해결/다시 열기 위치를 표시한다.  
> 삽입 파일: `images/anim-03-annotations.png`

## 4. 원하는 포즈를 보여 주며 지시하기

1. 문제 프레임에서 재생을 멈춘다.
2. Persona 미리보기의 본 조작으로 원하는 포즈를 만든다. 원본에 키를 굽는 작업과 구분한다.
3. 의도를 텍스트로 입력하고 **포즈 지시 저장**을 누른다.
4. 원본 대비 본별 로컬(부모 본 기준) 이동·회전 차이가 주석에 저장된다. 목록의 주석 텍스트 뒤에 `[Preview pose instruction; parent-space]`가 붙는다. 차이가 0.1cm / 0.5deg 기준을 넘지 않으면 저장할 포즈 변경이 없다는 메시지가 나온다.
5. 저장 후 미리보기 수정은 남아 있다. Persona의 본 수정 초기화 기능으로 직접 되돌린 뒤 원본 동작을 확인한다.

이 버튼은 애니메이션 수정 지시를 기록한다. 생성된 주석을 전달받은 작업자가 별도 작성 도구로 원본을 수정해야 한다.

> **캡처 자리 AN-04 — 포즈 지시**  
> 원래 포즈와 미리보기에서 바꾼 포즈를 같은 프레임에서 비교하고, 포즈 지시 저장 버튼과 저장 메시지를 표시한다. 초기화할 Persona 본 수정 위치도 설명한다.  
> 삽입 파일: `images/anim-04-pose-instruction.png`

## 5. 수정 후 이전 버전과 비교하기

1. 실제 AnimSequence를 수정한 뒤 다시 리뷰 묶음을 만든다.
2. 포즈 내용이 바뀌면 새 take가 생기고, 이전 take의 열린 주석이 이월된다. 내용이 같으면 최신 take를 갱신한다.
3. `review.md`의 테이크 비교에서 차이가 큰 본과 프레임 구간을 확인한다.
4. 주석 탭을 새로고침하고 **이전 테이크 고스트**를 켠다. 목록에서 비교할 이전 take를 고른다.
5. 현재 메시 위 자홍색 스켈레톤과 비교하며 타임라인을 움직인다. 고스트는 이전 포즈의 뼈대 표시이며 이전 메시를 완전히 복원해 렌더링하는 기능은 아니다.
6. 이월된 의견이 실제로 해결됐는지 확인하고 해당 주석을 해결 처리한다.

보존 기본값은 10개다. 최신 take와 최신 리뷰의 열린 주석이 처음 작성된 take는 보호되므로 10개를 넘게 남을 수 있다. 이전 `pose_md5_v1` take는 비교·고스트 대상에서 제외된다. 포즈 내용이 다른 v2 take가 둘 이상 있어야 v2끼리 비교할 수 있다. 같은 내용을 반복 실행해도 새 비교 버전은 생기지 않는다.

> **캡처 자리 AN-05 — 버전 비교**  
> 이전 take 선택 목록, 고스트 체크박스, 현재 포즈와 자홍색 스켈레톤을 함께 촬영한다. 이월 주석 표시도 한 항목 포함한다.  
> 삽입 파일: `images/anim-05-ghost.png`

## 6. 프로젝트에 맞는 검사 기준 설정하기

콘텐츠 브라우저의 Data Asset 생성에서 `JJAnimReviewProfile`을 선택해 사용자가 프로필을 만든다. Skeleton, 발 본, 관통 검사 본, 바닥 높이, 소켓·본 쌍과 검사별 임계값을 지정한다. 프로필이 없으면 이름으로 추정하며 경고가 붙는다.

> **캡처 자리 AN-06 — 프로필 에셋**  
> Data Asset 생성 대화상자에서 `JJAnimReviewProfile`을 고르는 화면과, 만든 프로필의 Details(Skeleton·발 본·바닥 높이·검사별 임계값)를 촬영한다.  
> 삽입 파일: `images/anim-06-profile.png`

| 검사 ID | 확인 내용 | 기본 임계값 |
|---|---|---|
| `foot_sliding` | 접지로 판정된 구간에서 발의 수평 이동 | 2cm |
| `penetration` | 지정 본이 바닥보다 내려간 깊이 | 1cm |
| `pop` | 본의 급격한 움직임 변화 | 회전 45deg; 이동 급변은 root 기준도 사용 |
| `joint_limits` | PhysicsAsset 관절 한계의 근사 초과 | 여유 5deg |
| `root_discontinuity` | 루트 이동의 급변 | 10cm |
| `loop_mismatch` | 루프의 시작·끝 포즈 차이 | 2cm |
| `socket_drift` | 지정한 소켓·본 쌍 거리의 변화 | 2cm |

접지 기본값은 높이 허용 3cm, 수직 속도 10cm/s다. 추정 프로필은 발 본별 클립 최저 높이를 바닥으로 쓰고, 수평 속도 50cm/s를 넘는 구간(발을 휘두르는 중)은 접지에서 뺀다.

`joint_limits`는 PhysicsAsset 제약 중 Limited 축만 검사한다(Free·Locked 축 제외). 같은 본·같은 축이 연속 프레임에서 초과하면 한 구간으로 합치고 가장 큰 초과량을 남긴다. 추정 프로필에서는 초과가 경고, 명시 프로필에서만 실패다. 검사는 앞 10000샘플로 제한되며 해당 시 경고한다. 루프 끝점과 내용 식별은 전체 포즈를 사용한다. 검사 통과만으로 연기 품질이 승인되는 것은 아니다.

현재 툴바 실행에는 프로필 선택기가 없으므로, 프로필을 지정한 검사는 에디터 콘솔로 실행한다. 주석 탭과 연결하려면 Output 인자는 생략해 기본 경로를 쓴다.

```text
JJAnimReview.Create /Game/Anims/Walk.Walk /Game/Review/WalkProfile.WalkProfile
JJAnimReview.Sheet /Game/Anims/Walk.Walk /Game/Review/WalkProfile.WalkProfile
```

프로필 없이 별도 출력 폴더를 지정하려면 중간 자리에 `-`를 쓴다. 예: `JJAnimReview.Create /Game/Anims/Walk.Walk - SessionA`. 다만 그 폴더는 현재 주석 UI가 읽는 기본 경로와 다르다. 툴바를 다시 누르면 프로필 없는 기본 요청으로 리뷰가 갱신된다.

## 7. AI에게 전달하고 반복하기

기본 출력의 take 폴더 경로와 수정 목표를 전달한다. 예: “이 리뷰의 미해결 주석을 반영해 줘. 먼저 review.md를 읽고, 필요하면 review.json을 확인해 줘.” AI 전달 원칙은 [AI_USAGE.md](../AI_USAGE.md)를 따른다.

화면 없는 수치 검사는 다음 명령을 사용한다. 경로는 환경에 맞게 바꾼다.

```powershell
& '<Engine>/Engine/Binaries/Win64/UnrealEditor-Cmd.exe' '<Project>/Example.uproject' -run=JJAnimReview -Asset=/Game/Anims/Walk.Walk -nullrhi -unattended -nosplash
```

선택 인자는 `-Profile=<에셋 경로>`, `-Output=<하위 폴더>`다. 종료 코드 **0**은 실행 완료·검사 실패 없음(경고는 가능), **1**은 검사 실패 있음, **2**는 실행 오류다. `-Sheet`를 주더라도 commandlet/nullrhi에서는 이미지를 만들지 않는다. 이미지가 필요하면 GUI에서 생성한다.

## 8. 막혔을 때

| 증상 | 조치 |
|---|---|
| 툴바 버튼이 없음 | AnimSequence 에디터인지, 플러그인 모듈 빌드·로드 여부 확인 |
| sheet.png가 없음 | GUI·렌더링·Preview Mesh, 리뷰 경고 확인 |
| 발 검사가 이상함 | 추정 프로필의 본·바닥 기준을 검토하고 명시 프로필 사용 |
| 주석을 추가할 수 없음 | 기본 출력에 리뷰 생성 → 탭 새로고침. 원본이 바뀌었으면 재생성 |
| 별도 Output 리뷰가 안 보임 | 주석·고스트 UI는 기본 출력 폴더만 읽음 |
| 이전 take가 고스트 목록에 없음 | 이전 v2 take 유무와 보존 여부 확인 |
| 손상·transaction 오류 | 주석 탭(읽기 전용)에서는 복구하지 않는다. 같은 에셋에 리뷰 묶음 만들기를 다시 실행하면 복구를 시도한다. 반복되면 오류가 지목한 폴더를 보존해 출력 에셋 폴더 밖으로 이동 후 재생성 |
| joint_limits 경고가 많음 | 추정 프로필이면 오탐일 수 있음. 메시지의 axis·angle·limit을 확인하고 필요하면 명시 프로필로 임계값 조정 |

## 검증 범위

2026-11-07 기준 자동화 테스트 21개(`JJAnimReviewKit.*`: 검사 7종·병합, 테이크 수명·보존, JSON 왕복, Markdown 예산, 주석 편집·포즈 지시, 비교, 시트 레이아웃, 경로·저장소 잠금)가 headless로 통과했다. 커맨드렛은 Ter 에셋 하나(`AS_PatrolLoop`)로 실행해 리뷰 묶음 생성을 확인했다. 툴바·주석 탭·실제 시트 이미지·고스트 화면은 실행 검증하지 않았다. 캡처 자리는 실제 화면을 넣을 위치 표시다.
